# Team Development Rules

1. Never push directly to main.
2. Every feature uses its own branch.
3. Create Pull Request before merging.
4. Never modify another member's feature without discussion.
5. Firebase schema changes require team approval.
6. Authentication architecture has one owner.
7. Security rules have one owner.
8. Shared components require team discussion.
9. Run the application and test before creating a PR.
10. Never commit passwords, API keys, private Firebase keys, or secrets.
11. Do not duplicate existing components.
12. Do not create unnecessary files or dependencies.
13. Keep naming conventions consistent (`elderId`, `linkedElderIds`, `relationships`).
14. Never trust frontend-only authorization.
15. Database/security changes must be reviewed before merging.
